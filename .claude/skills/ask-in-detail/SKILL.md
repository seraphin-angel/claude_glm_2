# Ask in Detail

プランや提案を実行する前に、不明点・曖昧な点をユーザーに深掘り質問するスキル。

## When to Use

- プランモードで「これで進めていいですか？」と確認する場面で、ユーザーが深掘りを求めたとき
- ユーザーが "Ask me in detail", "詳しく聞いて", "質問してから進めて" 等と入力したとき
- 大規模な実装前に要件確認が必要だと判断したとき

## The Process

### Step 1: コンテキスト分析

会話履歴を読み直し、以下を把握する：

- ユーザーが達成したいゴール
- 現在のプラン・提案の内容
- すでに明確になっている要件
- まだ曖昧・未定義な部分

### Step 2: SPACE フレームワークで質問を生成

以下の5軸で未解決の疑問を洗い出す。全軸から出す必要はなく、コンテキストに応じて重要な軸のみ使う。

| 軸 | 問い | 例 |
|----|------|-----|
| **S**cope（スコープ） | 機能の境界はどこか？何を含み、何を含まないか？ | 「管理者ユーザーもこの機能の対象ですか？」 |
| **P**erformance（性能・規模） | どの程度のスケールを想定するか？制約は？ | 「同時接続数は最大何件を想定しますか？100件をデフォルトにします」 |
| **A**ssumptions（前提・代替案） | 暗黙の前提は正しいか？他の選択肢はないか？ | 「認証はJWTを前提にしていますが、セッション方式の方がよいですか？」 |
| **C**orner cases（エッジケース） | エラー時・境界値・異常系はどう扱うか？ | 「ファイルが10MBを超えた場合、エラーにしますか？それとも圧縮しますか？」 |
| **E**xperience（体験・完了条件） | ユーザー体験のゴールは？何をもって完了とするか？ | 「処理中のローディング表示は必要ですか？」 |

### Step 3: フィルタリング（4-8問に厳選）

生成した質問を以下の基準でフィルタリングする：

**残す質問:**
- 回答によって実装が大きく変わるもの
- 現在のプランでは判断できないもの
- 間違った前提で進むとやり直しになるもの

**除外する質問:**
- コードを読めば自明なもの
- 一般的なベストプラクティスで答えが決まるもの
- 実装中に判断しても遅くないもの

### Step 4: 質問を提示

AskUserQuestion ツールを使い、厳選した質問をまとめて提示する。

**質問の形式ルール:**
- 各質問に番号を振る
- 質問の背景・理由を簡潔に添える
- 可能な限りデフォルト値や推奨案を提示する（ユーザーが「それでOK」と答えやすいように）
- 日本語で質問する

**提示テンプレート:**

```
プランを実行する前に、以下の点を確認させてください：

1. **[質問タイトル]**
   [背景・理由] → [デフォルト提案]

2. **[質問タイトル]**
   [背景・理由] → [デフォルト提案]

...

全てデフォルトでOKなら「全部デフォルトで」とお答えください。
個別に指定がある場合は番号で回答いただけます（例: "1はOK、2はXXXで"）。
```

### Step 5: 回答をプランに反映

ユーザーの回答を受け取ったら：

1. 回答内容をプランに反映する
2. 変更点があれば更新後のプランを簡潔に示す
3. 「全部デフォルトで」の場合はそのまま実行に移る

## Quality Signals

### Good Questions（実装を左右する具体的な質問）

- 「削除操作は論理削除（soft delete）と物理削除（hard delete）のどちらにしますか？既存DBのパターンに合わせて論理削除をデフォルトにします」
- 「エラー時のリトライは自動で行いますか？最大3回・指数バックオフをデフォルトにします」
- 「この API は認証必須ですか？現在の他のエンドポイントは全て認証必須なので、同様にします」

### Bad Questions（聞かなくていい質問）

- 「変数名はキャメルケースでいいですか？」→ プロジェクトの既存コードを見れば分かる
- 「テストは書きますか？」→ プロジェクトルールで TDD が必須と定められている
- 「TypeScript を使いますか？」→ 既存コードベースから自明
- 「エラーハンドリングはしますか？」→ 当然する。具体的な方針を聞くべき

## Communication

- ユーザーへの質問・報告は必ず **日本語** で行う
- 質問は丁寧だが簡潔に。冗長な前置きは不要
- 「全部デフォルトで」という回答パスを常に用意する
